# Rebuilding Lyceum Shorts with blog-webCLI

**Work in progress, not an editor-safe migration.** The approach below describes a local prototype, not the live site. Publishing from the editor bypasses the player integration. Do not use the editor to publish this prototype; the migration must be redesigned before these instructions are suitable for use.

{.lead} Six short educational films, their source scenes and tutorials, an existing HLS player and 131 MB of locally hosted video: this migration uses blog-webCLI for the shared site renderer while keeping Lyceum's specialized publishing pipeline.

The [live site](https://lyceumshorts.com/) is driven by [`lyceum.json`](https://github.com/tejaswigowda/lyceumshorts.com/blob/main/lyceum.json), without blog-webCLI. The prototype aims to preserve its public paths, metadata, scenes, captions, video renditions and no-third-party-request policy.

## 1. Keep the data model

Each film already has a structured record: claim, assumptions, demonstration-or-derivation status, colour key, scene repository and pinned render facts. The prototype now reads film and home-page content from canonical Markdown without overwriting it; `lyceum.json` still supplies player integration and content checks. Those checks do not yet validate the edited Markdown, and film pages and homepage cards must be maintained separately.

The film files keep their existing addresses:

```text
films/pythagoras/
films/a-plus-b-cubed/
films/hardy-weinberg/
films/area-volume/
films/projectile/
films/piston/
```

Preserving the path preserves existing links and embeds. The root index, About, Contribute and 404 pages are also generated through blog-webCLI. The six films are rendered in a separate folder-scoped blog build, so the index can retain its curated grouping by subject without making a second all-films feed.

## 2. Generate, round-trip and render

`scripts/generate.mjs` reads `pages/*.md`, `films/pages/*.md` and their respective `blog.json` files, then calls the pinned blog-webCLI `buildSite` for the actual pages. These source files are not regenerated by the build.

The HTML round trip is not a way around the authored-HTML allowlist: blog-webCLI parses, validates and re-serializes content before output. Site-owned player wiring happens afterwards in this explicit build adapter, not in an author's post or Custom JS setting.

## 3. Preserve the specialized player locally

The editor does not provide an adaptive HLS player, a caption-aware video element or transcript time links. Rather than add a provider-specific feature or move the 131 MB of renditions to a third party, the site build restores Lyceum's first-party player to film pages:

- the HLS playlists, segments, posters, captions and vendored hls.js remain in this repository;
- Safari uses native HLS; other supporting browsers use the local hls.js and player scripts;
- the full transcript remains readable without scripting, and timestamp links seek when playback is available;
- films retain their VideoObject metadata, exact scene links and existing canonical addresses.

This is a narrow, named integration in `scripts/generate.mjs`. It does not enable local or inline JavaScript in blog-webCLI. Index cards and ordinary content still use the shared renderer; the film page's trusted integration is kept distinct so it can be audited and tested.

## 4. Keep presentation and requests honest

The existing `assets/style.css` remains first-party and preserves the mobile-first light/dark palette, film cards, transcript and player. Its `prefers-reduced-motion` rules disable animation and transitions; scroll behavior is left intact so transcript navigation still works.

The build removes blog-webCLI's default Font Awesome link, then Lyceum's gate checks generated resource references. The only external URLs are ordinary links a person can choose to follow; the page itself fetches from its own origin. Player libraries and video files remain self-hosted.

## 5. Prototype build and verification

These commands describe the local prototype; its migration files are not on the public repository, so cloning the repository alone does not reproduce it.

The repository pins the shared renderer by commit in `.blog-webcli-ref`. From a checkout:

```sh
git clone https://github.com/tejaswigowda/lyceumshorts.com.git
cd lyceumshorts.com
git clone https://github.com/tejaswigowda/blog-webCLI.git .blog-webcli
git -C .blog-webcli checkout --detach "$(cat .blog-webcli-ref)"
npm run build
npm test
npm run check:page
```

The build verifies the pinned generator, reads Markdown and settings, regenerates static pages, then installs the player integration. `npm test` checks reproducibility, the Lyceum metadata/media/accessibility gates, and local paths. `npm run check:page` exercises the rendered index and film player in Chrome, including responsive layout and transcript seeking.

The prototype's `x-generator` metadata identifies blog-webCLI output. The live site is served from the repository root by GitHub Pages and does not yet include the prototype.

## Why use both showcases?

[webcli.app](https://webcli.app/) demonstrates a structured tool directory rebuilt as canonical pages and CSS. The Lyceum Shorts prototype explores a different boundary: preserving a specialized local media pipeline while sharing the renderer. Its editor-publishing limitation remains to be resolved.
