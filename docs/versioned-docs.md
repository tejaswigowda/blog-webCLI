# Versioned documentation

## Verification rule and withdrawn findings

**DOCS_FIXES_WORKORDER section A, DOC12 and DOC13 are withdrawn (November 18,
2026). Do not implement them.** The reported YAML body and missing head tags
were artifacts of an HTML-to-Markdown conversion, not established origin
defects. The converter synthesized metadata-looking frontmatter and consumed
head elements; this is not evidence that flat-permalink generation skipped
head assembly.

DOC14's assertions remain useful, but must inspect raw origin response bytes.
DOC15, DOC16, DOC17, DOC18, DOC19, DOC20 and DOC21 remain standing; this withdrawal
does not implement or close them.

**Standing verification rule:** a defect seen through a tool that transforms
the artifact is a hypothesis, not a finding. Before changing code, fetch raw
origin bytes (for example with `curl` or `fetch(...).text()`) and verify the
claimed defect there. Check generated metadata in the raw head and body
separately. A missing tag in converted Markdown, or synthetic frontmatter in
that representation, is not grounds for a generator fix.

## Configuration

Set `versions` in `blog.json`:

```json
"versions": [
  { "path": "v2", "ref": "main", "label": "2.0 (current)", "default": true },
  { "path": "v1", "ref": "v1.9.3", "label": "1.9" }
]
```

Paths are distinct, non-reserved lowercase slugs; exactly one entry is default. Historical refs must be locally available Git tags or full commit SHAs, not branches. Fetch tags and sufficient history before running `blog-webcli build` or `check`. A missing ref is refused before output is written. The default may use a local branch. The CLI reads committed sources, settings, theme pin, asset lock and manual order from each ref, not uncommitted working-tree changes. The current `blog.json` supplies the version list and deployment domain.

All versions, including the default, live under their prefixes. The site root redirects to the default. Each version has its own canonical URLs; old pages have a visible notice. Search and Atom feed are generated only for the default; the root sitemap points to the sitemaps of all versions. Normal sitemap and search settings still apply.

The editor publishes only the default version and requires editing its configured branch. It does not update historical snapshots. Run the CLI in CI after publishing to build all versions, and commit or deploy its output. Versioned pages do not use live rebuilding: the snapshots are regenerated by the CLI. Keep version prefixes exclusive to generated output.

## Existing `.html` addresses

Set `"pagePermalink": "/{slug}.html"` to publish standalone pages as files
instead of directory indexes. A `parent: guides` on `pages/intro.md` yields
`/guides/intro.html`; the source is still flat and post permalinks are unchanged.
Choose this form before publishing; do not toggle it on an established site
without auditing its URLs and redirects.

In paragraph and quote text, use two or more trailing spaces or a trailing
backslash to insert a hard line break. Both spellings are preserved on save and
render as `<br>`; ordinary soft breaks still join with a space. The editor uses
Shift+Enter to insert a backslash-style break. WordPress import is unchanged.

This still models independent pages, not books. Work-scoped numbering,
cross-page reference checking, and print/PDF are intentionally absent. Revisit
the document model when someone is actively writing a book to test it against.

## Strata migration verification

The [pre-migration inventory](strata-tutorial-inventory.json) records every
existing `.html` address, allowlist conflicts, and interactive embeds. The
migration initially left incompatible pages in place. The complete migration uses
`docs/about/tutorials` as the editor root, with 27 tutorial sources plus
`pages/home.md` for the index. Every old `.html` URL remains direct output.

For the historical partial migration, run
`node cli/strata-tutorial-migrate.mjs <Strata repository> --native` to make simple
headings and prose editable natively in Quill. It updates only migrated
tutorials and checks that the rendered markup is equivalent. Blocks with custom
markup that Markdown cannot reproduce (for example numbered step headings and
styled callouts) stay as HTML. Run the same command with `--check` to verify the
generated files are current.

The complete migration is staged with:

```sh
node cli/strata-tutorial-site.mjs <Strata checkout> --prepare <legacy-commit>
```

This inventories intentional markup substitutions in the tutorial folder's
`migration.json`: inline styles become theme classes, iframe examples become
sandboxed embed widgets, and the MP4 becomes a native-video widget. Headings,
plain paragraphs and isolated code blocks use native editor formats where they
preserve the content. Adjacent command/output code blocks remain separate HTML
blocks rather than being merged. Custom step headings, callouts, credits and
the index cards retain their markup.
Card-wide links exclude generated section anchors so clicking a thumbnail or
card background opens the tutorial, not an index heading.

The extracted first-party theme is MIT licensed with the owner's approval.
Commit its `theme/` files and `tutorial-enhancements.js` first, then use that
immutable commit to pin the theme and integrity-checked scripts:

```sh
node cli/strata-tutorial-site.mjs <Strata checkout> --build <theme-script-commit>
node cli/strata-tutorial-site.mjs <Strata checkout> --check
STRATA_CHECKOUT=<Strata checkout> node --test test/e2e/strata-tutorials.e2e.mjs
```

After migration, edit the Markdown in the new root through blog-webCLI; do not
repeat `--prepare` over edited sources. Normal editor publishing writes the
generated files alongside those sources and does not touch the Strata editor
outside the tutorial folder. GitHub Pages still serves `main:/docs` directly.
The archived `tutorials.json` catalogue continues to serve existing external
consumers; the editable home page owns the visible index.

To check a staged deployment, run
`node cli/strata-tutorial-inventory.mjs --verify http://localhost:5597/about/tutorials/`.
After publication, run `node cli/strata-tutorial-inventory.mjs --verify` against
the public site. Both commands check the same frozen list and reject redirects,
including meta-refresh stubs.

`publish-due` refuses due posts on a versioned site: publish and commit the source first, then build the refs.
